## Changes

- Previously staging search covered only a 1 m neighborhood of `frontier.middle` (the frontier point nearest the robot). A long curved frontier could have a usable endpoint outside that neighborhood. Now search multiple spatially separated anchors along the same frontier (0.40 m separation, maximum 24 anchors), preserving existing circular known-free clearance and endpoint navigation-cost limits.
- UNKNOWN visibility cone now points toward the frontier edge nearest the candidate viewpoint, rather than always toward the representative edge nearest the robot. Ray occlusion and minimum gain filtering remain.
- Soft scoring favors additional free room around an already safe candidate, up to 0.40 m using eight directional probes. This is only a preference, not a replacement for the full circular safety check or a guarantee of a medial-axis route.
- Existing current-map connectivity, LuckGrid path precheck, maximum prefix cost, local goal validation, controller and collision-monitor checks remain. No unknown-space driving or clearance reduction.

Current thresholds: minimum immediate visible unknown gain 0.50 m²; persistent branch gain 0.75 m²; reopen completed branch requires an additional 0.75 m². These are area counts, not required square shapes (equivalent squares about 0.71 m and 0.87 m on a side). Large invisible regions behind walls do not qualify merely by area. Live frontier matching/gain checks retain the ability to discard remembered branches observed from another route.

The existing DFS stack records siblings and selects the deepest pending sibling when a branch is exhausted. Backtracking uses a newly checked safe path, not blind reversal of wheel commands. This change improves viewpoint selection; it is not a rewrite or proof of complete exploration. It may still pause when all visible unknown regions lack safe reachable viewpoints. Selecting one best staging point per frontier can still miss an alternative with better visibility/connectivity; that remains a limitation.
