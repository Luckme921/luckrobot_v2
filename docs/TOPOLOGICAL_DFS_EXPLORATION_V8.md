# V8 拓扑 DFS 探索设计与验收边界

## 1. 本轮解决什么

稳定导航基线已经证明手动 `NavigateToPose`、RPP 跟踪、速度平滑和碰撞
监控能够工作。V7 的主要故障发生在更上层：它用“新旧前沿质心是否接近”
代替了路径拓扑，因此可能把机器人从分支 A 的前向目标切换到几何位置靠近、
但实际需要沿父边回退的目标。频繁换远目标、目标落在未知/高代价区，以及
行为树在不可达区域反复恢复，都是这一错误决策的后果，而不是底盘方向反了。

V8 只修改探索层，保持稳定基线中的以下文件逐字不变：

- `src/chassis_driver/src/chassis_node.cpp`
- `src/my_robot_navigation/config/nav2_params.yaml`
- `src/my_robot_bringup/config/collision_monitor.yaml`
- `src/my_robot_bringup/launch/smart_navigation.launch.py`

## 2. 状态机

```text
SELECT_ROOT
  -> FOLLOW_CHILD          选择一个当前可达、信息增益较高的子分支
  -> FOLLOW_CHILD          每次只发 <= 0.85 m 的白区安全连接点
  -> CLOSE_OR_PAUSE_CHILD  没有前向候选，或本次被临时障碍阻塞
  -> BACKTRACK_PARENT      从 LIFO 栈取最近兄弟，返回它的白区父分叉
  -> OPEN_REMEMBERED_CHILD 在父分叉按保存的子边方向重新绑定实时前沿
  -> FOLLOW_CHILD
```

根节点与每个子节点都可递归产生兄弟分支，因此自然得到
`A -> A1 -> A2 -> A3 -> B` 的深度优先顺序。DFS 栈只保存白区内、满足车体
余量的父分叉；未知前沿质心不会作为回退目标。

## 3. 选择不变量

1. 候选落脚点必须是 SLAM 白区，周围 `0.20 m` 都是已知自由栅格。
2. 候选点全局代价 `<= 20`，Nav2 路径前缀代价 `<= 40`。
3. 候选必须能在当前白区通过不穿未知、不切障碍角的 8 邻域路径连接到
   机器人；Nav2 随后仍会做第二次真实路径验证。
4. 普通分支的真实 Nav2 路径必须在保存航向前方 `70°` 内，且至少有
   `0.10 m` 正向投影。只有 `BACKTRACK_PARENT` 允许走反方向。
5. 两条白区路径的公共前缀终点才是父分叉。子边方向相差至少 `40°`
   才记为不同分支。栈先压入浅层分叉、后压入深层分叉；同一深度才按
   距离、转角和前沿长度排序，确保 A 内的 A2 先于根节点 B。
6. 已完成去重同时使用前沿距离、父分叉距离和子边方向；不能只按质心
   距离合并，否则新长出来的地图会被误判为已经探索。
7. 健康 Nav2 目标保持锁定。动态前沿刷新只能影响下一目标，不能在中途
   把当前目标抢走。

## 4. 临时障碍和静态死路

- 规划或跟踪一次失败：具体前沿冷却 `20 s`，当前子分支标记为“本次
  暂停”，转而尝试最近兄弟；不会触发探索行为树的 Spin/Wait/BackUp 循环。
- 当前分支连续 `3 s` 没有安全前向候选：认为该叶节点结束，进入 DFS 回退。
- 回父分叉本身也无有效路径或无运动：本次运行放弃该记忆分支，避免在
  狭窄椅子区无限往返。后续可在“动态障碍重访”阶段增加带次数上限的延迟队列。
- 全图连续 `45 s` 没有任何安全候选才宣布探索完成。

## 5. 为什么本轮不直接换 RL 或大型 3D 规划器

Jetson 有 GPU 不等于已经具备可部署的探索策略。RL 还需要与本车传感器、
动力学、碰撞边界一致的训练域、域随机化和实车安全验证；它不能修复当前
明确可观测的“分支拓扑未建模”缺陷。TARE/GBPlanner 的局部-全局图思想值得
借鉴，但其公开工程面向 ROS 1 和 3D 点云/体素栈，直接移植会同时更换地图、
规划器和接口，无法保住当前已经验收的 ROS 2 Humble 2D 导航基线。

较新的 `frontier_exploration_ros2` 支持 Humble，并实现 MRTSP、提前抢占和
失败抑制，适合作为后续仿真/录包回放 A/B 基准；它优化的是前沿访问序列，
并不等同于这里要求的显式 DFS 分叉语义。V8 先把可解释、安全、可观察的
树式策略跑通，再决定是否移植其中的预取机制。

## 6. 为什么暂不提前发送下一个目标

`NavigateThroughPoses` 可以让控制器沿中间姿态连续通过而不在每一点停下，
但探索地图在运动中不断扩展，预先组成的后续点可能很快失效。直接用新的
`NavigateToPose` 抢占旧目标也只有在“下一目标仍属于同一子边”已经被实车
证明后才安全。V8 先把局部步长从 `0.65 m` 增至 `0.85 m`，把到点刷新等待
降至 `0.35 s`，减少停车次数；完成三轮拓扑验收后，再把受控预取作为 V9
单独 A/B，不能在同一轮同时修改分支选择和动作生命周期。

## 7. 实车通过标准

- 连续至少 5 个绿色前进目标，步长均 `0.25..0.85 m`、代价均 `<= 20`；
- 除明显弯道外，同一分支不出现接近 180° 的无理由反转；
- 分支切换前先出现黄色父分叉，随后橙色回退目标，回到分叉后才打开紫色
  子分支；
- 临时人/纸箱触发失败时不会连续向同一区域轰炸目标，也不会无限恢复；
- `/cmd_vel_safe` 与碰撞监控继续正常，手动 RViz 单点导航基线不改变；
- 上传诊断包后再决定 V9 是否启用同分支目标预取。
