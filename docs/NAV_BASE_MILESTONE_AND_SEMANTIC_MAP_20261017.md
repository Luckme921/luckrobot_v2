# 导航底盘阶段里程碑与语义地图路线（2026-10-17）

## 已验证范围

- 新夹具未改变轮距、轮径及相机、雷达、IMU 安装位姿；此前数次停转、漂移的解释可能混入了轮子打滑，不能再把它们全部归因于软件。
- 轮速＋IMU EKF、2D 激光 SLAM、Nav2、深度相机安全层仍是生产导航链。人工测试中，两次原地旋转、一次直线、一次直线加转弯及多次短距离目标到达；动态障碍移开后重新通行也有成功案例。这是阶段性通过，不等于所有光照、地形和长时运行已认证。
- cuVSLAM 只在旁路测试。2026-09-21 的约 535 秒记录中视觉路径尺度和协方差严重异常；2026-10-17 新夹具后静止复查中，健康门控因位置协方差过高而接受 0 帧。视觉里程计不接入主 EKF、主 TF 或 Nav2。见 `VSLAM_FIELD_VERDICT_20260921.md`。
- 轮式 yaw 旁路 A/B 没有显示值得替换当前主 EKF 的收益，不为追求“更多融合”而更改稳定主链。

## 语义地图：在现有 2D 地图上增加对象层

不依赖 cuVSLAM 重建定位。继续用 `/map` 和 `map -> odom -> base_footprint`，相机彩色图 `/camera/color/image_raw` 与深度图 `/camera/depth/image_raw` 做对象观测：

1. 用轻量目标检测模型识别预先限定的类别（先从人、椅子、桌子、门开始），在 Jetson 上以低频、可降级的旁路推理运行；不把检测线程放进底盘控制或安全制动链。
2. 用同一时刻的深度、相机内参与外参把框内可靠像素反投影至相机坐标，再用有时间戳的 TF 投到 `map`。深度无效、TF 过期、位置不确定度过大时丢弃观测，不能猜坐标。
3. 按类别、距离和时间做跨帧关联。保存对象 ID、类别、地图位置、协方差、置信度、首次/末次观测时间及观测次数；只有多次稳定观测才成为持久语义地标。地图重定位/坐标跳变时暂停写入并重新校验地标。
4. 人等动态目标只进入短时跟踪与现有安全/代价地图，不写为永久障碍。椅子等可移动对象允许位置更新与过期；墙、桌腿等碰撞几何仍由激光/深度代价地图负责。语义地图是独立图层，不覆盖 SLAM 占据栅格。
5. 初始验收先离线回放带标注的图像＋深度＋TF 包，核对类别误报、投影误差及对象重识别，再做在线旁路。生产导航不依赖该图层才能继续工作。

## 资源与安全门槛

这台 Orin Nano Super 为 8 GB；本机生产导航空闲可用内存约 3.8–4.0 GiB。cuVSLAM 静止旁路额外占用约 0.7 GiB 可用内存，但这只是一次快照，不代表峰值。不能仅凭 TOPS 或单次 `docker stats` 宣称可以同时运行任意模型。

建议先用小模型、彩色图降采样和约 5 Hz 推理作为**测试起点**，根据实测调整。记录推理延迟 p50/p95、总内存/GPU/CPU、相机与 `/scan_camera` 发布率、控制周期和 Nav2 超时。若避障扫描、TF 或控制出现丢帧/超时，立即关闭语义旁路。只有连续多场景测试保持导航表现不退化，才考虑提高频率或增加类别。
