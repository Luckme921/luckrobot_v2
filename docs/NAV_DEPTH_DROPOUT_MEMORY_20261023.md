## 相机障碍记忆

原配置已将 `/scan_camera` 接入全局和局部独立相机障碍层，与雷达层分开。`observation_persistence: 0.0` 是观测缓存时长，不等同于已标记栅格立即消失。

发现两个确定的代码边界：标准 ObstacleLayer 随全局地图 resize 重建栅格；luck_full 的 no-path 恢复还会自动 clear_entirely_global_costmap。当前包中全局地图尺寸/原点约变化 17 次。这些机制可以丢失视野外障碍，但未从本包逐物体标注确认用户指的那一个障碍具体在哪次被清掉。

已部署：

1. 全局相机层改用 `PersistentCameraLayer`，尺寸/原点变化时保存仍占用的世界坐标，重新投影回新栅格。保存原始坐标锚点，避免反复重采样导致逐次漂移；真正已被清除的单元不复活。
2. 保留有限相机观测的正常 clearing；不将无深度/视野外区域自动判为空闲，不添加简单超时消失机制。
3. luck_full 单目标行为树不再因无路径自动清空全部全局障碍，保留有界等待/重规划。显式人工 reset、重启、新地图仍会清除记忆；未声称跨会话永久语义地图。
4. 全局相机标记范围 1.5 → 2.5 m，清除范围 2 → 3 m，与局部匹配；未扩大实际相机检测能力。

测试覆盖：39 次尺寸/原点连续改变仍保持同一世界位置；已清除障碍不恢复；pluginlib 动态加载成功。C++ 测试使用运行时检查，Release 构建也执行检查。

边界：本改动不是完整三维体素地图。相机不可见时无法知道物体是否被搬走；局部滚动地图及视场盲区仍存在，不能用“全局里有记忆”代替实际局部避碰验证。SLAM 大回环校正、重定位及动态物体更新需单独验收。
